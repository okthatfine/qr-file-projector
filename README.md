# 文件放映机 / QR File Projector

把文件拆成循环播放的二维码。接收者打开接收页、允许相机取景，从任意一帧开始收。画面短暂遮挡时，后续循环能补回缺块。所有观众看到相同的数据；适合公开分发的例程、接线表和提示单。

在这段模拟演示中，前 6 秒遮住了二维码。播放到第 24 秒，接收端只收齐了 18 块；下一轮补回开头的 6 块，还原出完整的 12 KiB 文件。视频中的二维码可以扫码。[观看或下载 30 秒演示（MP4）](demo/six-missed-frames.mp4)

## 本地运行

使用 MoonBit（开发时 moon 0.1.20261119）和 Node.js 22 或更新版本。在仓库根目录执行：

```sh
npm ci
npm run build
moon test --target js
npm test
python -m http.server 8000 --directory dist
```

在本机打开 http://localhost:8000。手机取景需要 HTTPS，可把整个 dist 目录部署到 HTTPS 静态站点。两端打开页面后可断网传输。导入或导出 GIF 前，浏览器需能加载同站的 film-worker.js。

## 两分钟试用

1. 选择一份最多 64 KiB 的文件，点击「开始放映」。首次使用建议选 256 字节和每帧 1.1 秒。
2. 手机打开同一工具的「扫码接收」，对准完整二维码，留出白色边框。看到块数增长后遮住镜头，再移开。
3. 收满后点击「保存」。接收另一份文件前请清空进度。距离较远时可降低每块字节数、延长停留时间。
4. 漏扫时可保存 .qfc 进度文件，稍后恢复或合并同一份文件的进度。把接收端的补播凭条粘贴到发送端，使用原文件和原块宽即可只播缺帧。
5. 「导出循环 GIF」可保存整段放映或补播片段。接收端可用相机扫 GIF，也可直接导入放映 GIF。可先用 [八帧示例](demo/chunks.gif) 试用，导入后会还原 chunks.mbt。

## 开发与验证

运行 `node scripts/count-source.mjs` 可复核 622 行 MoonBit 生产源码。统计排除测试、生成文件、依赖、空行、注释和仅含标点的行。MoonBit 实现进度恢复与合并、补播凭条、原文件重组，以及双色循环 GIF 的 LZW 编解码。浏览器负责相机、画码和读码、文件操作及 SHA-256。

MoonBit 库负责帧的序列化、解析和校验，计算切块范围，并保存乱序到达的分块。每帧的 JSON 数组依次包含协议标识 QFP1、SHA-256、文件名、文件长度、块宽、零基序号、Base64 载荷。接收端使用浏览器的 Web Crypto 校验整文件摘要。屏幕内容对现场观众可见。

测试包括空文件、末块、重复与冲突、跨版本、模拟缺 6 块后补齐，以及「生成二维码 → 渲染像素 → 解码 → 还原原文件」的往返测试。相机距离、投影亮度与接收时长需要现场实测。

构建后可单独复现申报书中的遮挡实验：

```sh
node --test --test-name-pattern="12 KiB" tests/optical.test.mjs
```

实验把 12 KiB 样本按 512 字节拆为 24 帧。第一轮跳过开头 6 帧，将其余二维码渲染成像素并用 jsQR 解码，确认只收到 18 块。下一轮补扫前 6 帧，逐字节比对原文件并输出 SHA-256。整个实验在本机内存中运行，无需摄像头。
